# 저장 오답노트

## 겪은 일
- (17·18) 컴퓨터에 덮어쓰기 저장할 때 첫 저장에 옛 파일이 들어가는 일이 잦음 → 파일을 `/mnt/user-data/outputs/`에 다 쓴 **뒤에** device_commit_files(force) 실행(동시에 실행 금지) → device_list_dir로 크기가 깃허브본과 같은지 확인, 다르면 한 번 더 저장하고 다시 확인.
- (공통) 얕은 clone 상태로 오래 작업한 뒤 푸시하면 거부될 수 있음(413) → 푸시 전 `git fetch origin main` 후 rebase.
- (공통) 컴퓨터가 꺼져 있거나 연결이 끊겨 있으면 깃허브·아티팩트만 먼저 저장하고, 컴퓨터 저장이 남았다고 사용자에게 알림.
- (공통) 새 hak 파일을 올리거나 이름을 바꾸면 `makeindex.py`로 목차(index.html)도 다시 만들어 함께 저장.
